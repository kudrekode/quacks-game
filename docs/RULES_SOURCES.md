# Rules Sources

## Priority-ordered local sources inspected

1. `preDocs/Quacksalber_Rules_English_v1.pdf` - all 11 pages; authoritative setup, round/evaluation order, all four ingredient sets, two-player black rule, final scoring, and variation boundary.
2. `preDocs/Fortune-telling_Cards.pdf` - both pages; all 24 German-title/English-translation entries and their visual timing grouping.
3. `preDocs/individualBoard.webp` - pot spiral, repeated purchasing values, VP, ruby spaces, droplet/rat/flask areas, and spoon endpoint.
4. `preDocs/mainBoard.jpg` - 1-50 score loop, rat-tail boundaries, round milestones, evaluation sequence, and shared hierarchy.
5. `preDocs/Deluxified_Tokens_Quacks_of_Quindlinburg_all_sheets.pdf` - all three pages; color/value differentiation reference only.
6. `preDocs/prompt_1.md` - stage scope, output contract, source priority, and asset restrictions.

## External corroboration

Used only after the local board image left values impractical to tabulate confidently:

- [Original English rules mirror](https://cs.uwaterloo.ca/~dtompkin/archive/dtlib/base/The%20Quacks%20of%20Quedlinburg.pdf) - corroborated evaluation wording and spoon endpoint.
- [Huenemoerder et al. open-source RL implementation](https://github.com/huenemoerder/quacks-rl) - corroborated the pot money/VP/ruby arrays and six bonus-die faces. It is secondary evidence, not authoritative, and its unrelated game simplifications were not adopted.
- [Schmidt Spiele ingredient almanac mirror](https://c.tabletopia.com/games/the-quacks-of-quedlinburg/rules/88220-quacksalber-quacks-almanac-gb/en) - corroborated set descriptions where PDF extraction crossed pages.

## Copyright handling

Documents contain mechanical facts and original concise paraphrases. No supplied image is copied to production, no long card wording is reproduced, and commercial artwork remains reference-only. Product UI must follow `ASSET_POLICY.md`.

## Audit result

All nine rounds, default ingredients, 24 Fortune cards, board spaces, final-round behavior, scoring/purchasing order, and hidden-information boundaries are represented. Ambiguities and decisions are centralized in `DECISIONS.md`.
